# 音频转 MP3（ffmpeg.wasm，纯本地）

## 一、为什么「上传多大、下载还是多大」

不是没生效，是**参数本身压缩不动**。MP3 是有损编码：

1. 源文件已经是 MP3 / AAC / M4A，且码率等于或低于目标码率（例如 128k MP3 → 128k MP3），
   解码再编码一次只会重新生成一帧帧数据，体积基本持平甚至略大。
2. 源文件是 WAV / FLAC（无损），转 128k MP3 才会明显变小，通常能到原来的 1/5 ~ 1/10。
3. 「声道保持原样 + 采样率保持原样」不会主动降体积；要变小必须降码率 / 降声道 / 降采样率。

真正能压小体积的参数组合（按效果排序）：

| 目标 | 设置 |
|---|---|
| 体积减半 | 声道选「单声道」 |
| 体积减半 | 采样率选 22050 Hz |
| 语音场景最小 | 64 kbps + 单声道 + 22050 Hz + 语音优化预设 |
| 保持音质但比 CBR 更小 | 比特率模式选「VBR 可变质量」，质量 4 或 2 |

## 二、这版相对原代码修了什么

1. **核心来源只剩内置**。原代码先试本地、再试 npmmirror、再试 jsdelivr，
   npmmirror 的 `/@ffmpeg/core/0.12.10/files/...` 路径现已不可用（403/404），
   于是每台机器都要等两轮超时才加载成功，看起来像"掉链子"。现在只读 `core/` 与 `core-mt/`，完全离线。
2. **多线程核心补了线程数**。`-threads` 取 `hardwareConcurrency-1`（上限 4），
   原来多线程核心也会按 1 线程跑。
3. **进度解析更稳**。同时读 `progress` 与 `time`（ffmpeg.wasm 0.12 事件同时给这两个字段），
   并显示已处理音频时长。
4. **参数大幅扩充**：比特率模式（CBR/ABR/VBR）、编码效率 `-qscale:a`、预设、音量归一化/增益、
   采样率新增 16k/8k、截取片段、`-probesize` 首帧容错。
5. **新增「⬇ 下载本页源码」**：把当前 index.html、启动脚本、lib、core、core-mt 全部打成
   `base-html.zip` 直接下载，解压后双击 `启动.bat` 即用，无需再找我要包。
6. 转完后若输出体积没变小，日志里会主动提示原因与可用的降体积参数。

## 三、目录结构

```
index.html            页面（单文件，全部逻辑在此）
server.js             Node 本地服务（开启 COOP/COEP，推荐）
server.ps1            PowerShell 本地服务（无 Node 时兜底）
启动.bat              一键启动
README.md             本文件
lib/                  ffmpeg.wasm 0.12.15 ESM 模块 + jszip.min.js
core/                 @ffmpeg/core 0.12.10（单线程核心，约 32MB）
core-mt/              @ffmpeg/core-mt 0.12.10（多线程核心，约 32MB + worker）
```

## 四、用法

1. 双击 `启动.bat`，浏览器会自动打开 `http://127.0.0.1:8787/`。
   **不要用 file:// 双击打开 index.html**，浏览器禁止 file:// 页面加载 Worker 与 wasm。
2. 选文件 → 调参数 → 开始转换 → 下载 MP3。
3. 多线程按钮只有在页面处于 cross-origin isolated（即通过上述脚本启动）时才可点；
   Firefox / 部分安卓浏览器即使带 COOP/COEP 也不稳定支持，日志会说明原因并自动回退单线程。

## 五、已知边界

- 单线程核心转码速度约为原生的 1/3 ~ 1/5，一首 5 分钟歌曲通常几十秒。
- 输入文件整体要写进浏览器虚拟内存，建议单个文件不超过 500MB，否则可能标签页崩溃。
- 默认 ffmpeg.wasm 构建不含 libmp3lame 之外的所有编码器，本页只用 libmp3lame。
